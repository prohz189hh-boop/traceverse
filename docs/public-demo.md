# Public interactive demo

**[Open TraceVerse in your browser](https://prohz189hh-boop.github.io/traceverse/)**.

No account, API key, paid API, cloud database, or local installation is needed. This is a static GitHub Pages application using explicitly synthetic telemetry. The metrics are demonstration values generated by bundled scenarios; they do not describe real external services.

## Explore in a minute

1. Select a node in the 3D universe, or use a service button in the sidebar. The inspector shows dependencies, observed span counts, latency, and errors.
2. Choose a scenario beneath the graph and run it. Adjust demonstration traffic intensity for more concurrent synthetic requests.
3. Open **Traces**, select a trace, and follow its parent/child spans and waterfall. Open **Errors** after API failure to inspect the recorded error evidence.
4. Try **Focus**, **Reset camera**, zoom/orbit controls, category filters, and **2D/3D** switching.
5. Open **Settings** for low/balanced/high graphics and reduced motion. Capture a session in **Sessions**, then use replay speed, play/pause, and the timeline.

On touch devices, drag to orbit and pinch to zoom where the browser supports these gestures. The service/trace HTML controls remain available when selecting a small 3D object is difficult. On narrower screens, navigation scrolls horizontally and the inspector moves below the main panel.

## Synthetic scenarios

| Scenario           | What to inspect                                                                                             |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| Successful sign-in | A successful frontend/gateway/auth/users path, status, duration, and child spans                            |
| Slow database      | A database operation above the default 500 ms warning threshold; compare its duration with its parent trace |
| API failure        | Error status and exception type, highlighted dependency, and affected trace hierarchy                       |
| Heavy traffic      | Multiple concurrent synthetic traces; increase/decrease intensity from 1 to 6                               |
| Recovery           | Subsequent successful spans showing recovery from the example failure                                       |

The combined graph contains frontend, API gateway, auth, users, orders, database, cache, payment simulator, and notifications. Parent-child relationships and database attributes in the synthetic span records create its connections. Switching scenarios changes the demonstration evidence, not the state of a real application.

Recovery does not prove an external service is healthy. Historical error spans can remain visible in a retained session, and replay is always a historical view.

## Data and privacy

The public build offers Synthetic and synthetic-session Replay. It does not start Node.js, OpenTelemetry exporters, the collector, SQLite, or the real example services. It never attempts collector API/WebSocket connections, and it rejects any session import containing `live` or `demo` spans. Exporting a public-demo session creates a synthetic JSON download on your computer.

Up to six saved synthetic sessions and preferences are stored in your browser, using separate keys from the local build. Delete sessions in **Sessions** or clear the site's browser storage to remove saved data/preferences. Saved sessions do not use real collector retention. GitHub Pages receives normal static-file requests; TraceVerse does not send application telemetry to a hosted backend. [Privacy details](privacy.md).

To inspect your own app, [install the local application](installation.md) and [configure its SDK/exporter](instrumentation.md). Real local **Demo** mode runs instrumented Express services and SQLite; it differs from the public synthetic demonstration.

## Build and verify locally

```sh
npm ci
npm run build:demo
npm run preview:demo
```

Open http://127.0.0.1:4173/traceverse/. Output is `apps/web/dist-public`; the preview is a static server. To run browser checks, stop a separate preview if it occupies the test port, then run:

```sh
npx playwright install chromium
npm run test:static
```

The Pages workflow builds this public output and deploys it through GitHub Actions. Hosting requires repository Pages support and Actions deployment permission. Configuring a workflow alone does not establish that publication succeeded; actual deployment and remote verification are recorded in [PROGRESS.md](../PROGRESS.md).
